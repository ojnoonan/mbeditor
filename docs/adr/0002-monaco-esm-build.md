# ADR-0002 — Isolated maintainer-only build for Monaco (ESM)

- **Status:** Accepted
- **Date:** 2026-06-10
- **Deciders:** Anthony Georges
- **Relates to:** [ADR-0001](0001-no-frontend-build-step.md)

## Context

mbeditor pinned `monaco-editor` at **0.52.2**. From **0.53.0**, Monaco's changelog states:

> ⚠️ This release deprecates the AMD build … Please migrate to the ESM build.
> - Internal AMD modules are no longer accessible.
> - Custom AMD workers don't work anymore out of the box.

The editor was loaded entirely via that now-deprecated AMD build:

- `loader.js` + `require(['vs/editor/editor.main'])` with `require.config` paths,
- a curated subset of the AMD `vs/` tree (committed under `public/monaco-editor/vs/`),
- two hand-written custom AMD workers (`public/monaco_worker.js`, `public/ts_worker.js`)
  that `importScripts('.../vs/base/worker/workerMain.js')`.

In 0.55.1 the `min` build is esbuild-based with hashed chunk filenames; `workerMain.js`
no longer exists, `basic-languages/<lang>/<lang>.js` collapsed into flat chunks, and the
nls files were renamed. **0.52.2 is the last release compatible with the AMD setup** — i.e.
the ceiling under a literal reading of "no build step." (See issue #61 for the full options
analysis.)

ADR-0001 draws the important distinction:

- **Consumer-facing (hard line):** anyone who `bundle install`s mbeditor must not need
  Node/npm/a bundler for the editor to work.
- **Maintainer-facing (nice-to-have):** edit a file, reload, no compile in the loop.

Monaco's ESM build requires a bundler to assemble the editor + workers. That conflicts with
the maintainer nice-to-have, but **not** with the consumer hard line — as long as the
bundler runs at maintainer time and the output is committed and shipped in the gem.

## Decision

Consume Monaco as **ESM, bundled at maintainer time by an isolated esbuild script**, and
commit the prebuilt artifacts to `public/monaco-editor/`. Everything else in the frontend
keeps ADR-0001 unchanged.

- `build/monaco/build.mjs` (run via `npm run build:monaco`) produces, into
  `public/monaco-editor/`:
  - `monaco.js` — IIFE, sets `window.monaco` (entry: `editor.main`, all languages)
  - `monaco.css` + `codicon.ttf` — extracted editor styles + icon font
  - `editor.worker.js`, `json.worker.js`, `css.worker.js`, `html.worker.js`,
    `ts.worker.js` — standalone classic workers
  - `monaco-vim.js` — the upstream prebuilt UMD, copied as-is (its browser branch binds
    to the `window.monaco` global; rebuilding it from ESM would duplicate Monaco)
- These are loaded with plain `<script>`/`<link>` tags. No `loader.js`, no AMD, no
  `require()`. Workers are wired through `MonacoEnvironment.getWorker` returning
  `new Worker('.../monaco-editor/<label>.worker.js')`.
- `monaco-editor`, `monaco-vim`, and `esbuild` are **devDependencies only**. The committed
  artifacts under `public/` are what ships and what consumers load.

### Why this stays inside ADR-0001's hard line

The build is **maintainer-only**. A consumer who `bundle install`s mbeditor still needs
zero JS tooling — they receive the prebuilt `public/monaco-editor/` files in the gem, the
same way they already receive every other vendored artifact. Conceptually Monaco becomes a
vendored artifact regenerated by a documented script, not a live build dependency.

## Consequences

- **Only Monaco** has a build step, and only when bumping `monaco-editor` / `monaco-vim`.
  App code and the other vendored libs (`vendor/assets/`) are still edited directly.
- Upgrading Monaco is now `npm install monaco-editor@X monaco-vim@Y && npm run build:monaco`,
  then commit `public/monaco-editor/` — a supported path that survives future releases.
- The committed bundle is larger and unsplit (~4 MB JS): the prior curated-language subset
  is dropped in favour of the full set. Acceptable for a dev-time tool; language subsetting
  via a custom entry is a possible future optimisation.
- Removed: the AMD `vs/` tree, `public/min-maps/`, the `monaco_worker`/`ts_worker`
  controller actions + routes, and the vendored `monaco-vim.js` asset.
- `public/monaco-editor/` is now **generated output committed to the repo**. Always
  regenerate via `npm run build:monaco`; never hand-edit it. The build writes a
  `VERSIONS` stamp recording the exact `monaco-editor` / `monaco-vim` / `esbuild`
  versions that produced the artifacts, and those devDependencies are pinned exactly
  in `package.json` so rebuilds are byte-reproducible across maintainer machines.
- Issue #61 (evaluate Monaco ESM migration) is resolved by this ADR.
